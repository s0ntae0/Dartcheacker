# 사용자 흐름 (기능명세서 §3용)

```mermaid

  B --> C[공시로 확인 ⌘↵]

  C --> D[결과 카드 A: 위험 신호 지수<br/>점수·등급·근거·패턴·진행 단계·다음 단계 예고]
  D --> E[원문 하이라이트]
  E --> F[결과 카드 B: 주장별 공시 대조<br/>확인됨/일부 상이/공시 근거 미확인/공시 대상 아님/검증 범위 밖]
```

## 2. 단계별 설명

| 단계 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 접속 | 모바일/PC 브라우저로 URL 접속 | 좌측 사이드바(새 검사·이력·바로가기·오늘 통계) + 메인 빈 상태(h1 "받은 메시지, 공시로 확인하세요", 입력 박스, 예시 칩, 판정 기준). 모바일은 상단 바의 햄버거로 사이드바를 드로어로 엶 |
| 2 입력 | 리딩방·SNS 메시지를 그대로 붙여넣기. 처음이면 예시 칩 클릭 | 글자 수 카운터(최대 4,000자), 입력 높이 자동 확장. **예시 칩 클릭 시 입력창을 채우고 자동으로 검사 실행** |
| 3 검사 | "공시로 확인" 클릭 또는 ⌘/Ctrl+Enter | 버튼 "확인 중…"(중복 클릭 방지). 서버 파이프라인 실행(목표 15초 이내). 성공하면 결과가 사이드바 이력에 추가됨 |
| 4 위험 신호 지수 | 점수·등급 확인 | 큰 숫자 0~100 + 등급 태그(낮음/주의/높음/판단 유보) + 근거 문구·일치 개수 + 미터, 우측 "최종 확인 시각"과 "결과 요약 복사". hard 신호면 지수 카드 아래 배너. 일치한 수법 카드에서 인용 구절과 "법적 근거와 출처" 토글. 노트 카드에 "반대로 생각해보면"·"이 다음에 올 수 있는 것" |
| 5 원문 확인 | 어느 구절이 걸렸는지 확인 | 원문 카드에 매치 구절을 mark로 표시(강한 패턴 적색·약한 패턴 주황) |
| 6 공시 대조 | 메시지 속 주장(예: "OO 1,000억 수주")이 공시로 확인되는지 확인 | 주장/판정/근거 3열 표: 판정 태그 + 설명(공시 금액·방식·차이율) + 공시 의무 안내 + "DART 원문 {접수번호} ↗" + 정정 반영 |
| 7 행동 | 안내에 따라 행동 | 등급별 행동 요령 번호 목록. 신고·상담처는 사이드바 바로가기(전화는 `tel:`) |
| 8 이어서 검사 | 다른 메시지를 하단 고정 입력창(dock)에 붙여넣기 | 새 결과로 교체 + 이력 추가 + 위로 스크롤. 사이드바 "＋ 새 검사"는 빈 상태로 복귀 |
| 9 이력 | 사이드바(모바일은 드로어)의 이전 검사 클릭 | 서버 호출 없이 저장된 결과를 즉시 표시(브라우저 localStorage, 최대 20건). "다시 검사"로 같은 텍스트 재검사, × 로 삭제 |

## 3. 서버 처리 흐름

```mermaid
sequenceDiagram
  participant U as 브라우저
  participant S as /api/check
  participant L as CLOVA HCX-005
  participant DB as Supabase
  participant D as OpenDART
  U->>S: POST {text}
  S->>S: 검증(10~4000자)·해시·rate limit
  S->>S: 규칙층 매치(패턴 16·정상 신호 4)
  par 병렬(각 12초 타임아웃)
    S->>L: 패턴 판정(3단)
    S->>L: 주장 추출

  loop 주장마다
    S->>DB: find_corp(기업명)

  end
```

## 4. 예외 흐름

| 상황 | 사용자에게 보이는 것 |

| 10자 미만 / 4,000자 초과 | 입력창 아래 안내 문구(400) |
